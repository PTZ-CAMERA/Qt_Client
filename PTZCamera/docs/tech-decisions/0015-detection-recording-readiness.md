# 탐지·저장 진단과 녹화 대기 상태

문제: Events 구독 성공과 실제 탐지 샘플 저장을 구분하기 어렵고, 미확정 녹화를 녹화 없음으로 표시했다.

기존 QWebSocket/VmsClient/Qt Widgets를 재사용한다. GET_METADATA_STATUS를 2초마다 요청하며 in-flight 요청은 하나만 유지한다. cameraId와 requestId를 확인하여 카메라 전환 전의 결과를 무시한다. DB 개수는 보존 기간 내 탐지 샘플 수이며 사람 수가 아니다. 마지막 수신·저장 시각과 녹화 상태를 함께 표시한다.

클라이언트에서 알림 개수를 세는 대신 VMS DB를 조회하므로 늦게 접속해도 저장 수가 일치한다. 새 연결이나 3초 이상 지난 탐지 값은 없음으로 추측하지 않고 미확인으로 표시한다. 구독 오류와 상태 조회 실패도 구분한다.

녹화 조회는 RECORDING_IN_PROGRESS/NO_RECORDING_AT_TIME/기타 실패 이유를 구분한다. 미확정 파일은 재생하지 않는다. 재조회는 사용자가 녹화 완료 후 실행한다.

Playback에 2초 사전 재생 옵션을 추가했다. 서버가 반환한 offset은 보존하며 선택한 옵션만 UI 재생에 반영한다. 기본 ON, 해제 가능, 동일 파일 0ms에서 하한 제한. 정확한 탐지 프레임 동기화나 원격 파일 전송을 의미하지 않는다.

실제 Pi 탐지-검색-재생 전체 시험은 별도 필요하다. Pi의 추적 OFF 시 탐지 활성 설정도 확인해야 한다.
